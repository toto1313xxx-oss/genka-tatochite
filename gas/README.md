# 伏見堂 原価符牒計算機 r3 — 新規GAS導入

## 初期設定
1. 既存スプレッドシートをバックアップするか、新しいスプレッドシートを作成。
2. スプレッドシートの「拡張機能 → Apps Script」を開く。既存GASを上書きせず、新規シートで試すことを推奨。
3. gas/Code.gs の全文を新しいプロジェクトの Code.gs に貼り付け、保存。
4. setupFushimidou を一度実行し、権限を承認する。新規の「伏見堂_r3_操作台帳」だけを作成する。
5. プロジェクトの設定 → スクリプト プロパティにある FS_MANAGER_TOKEN と FS_STAFF_TOKEN を確認する。GitHubやチャットに公開しないこと。
6. デプロイ → 新しいデプロイ → ウェブアプリ。実行ユーザーは自分。アクセスは匿名で呼び出せる設定（利用可能な場合は「全員」）とする。公開URLは /exec。
7. r3 HTML の設定に /exec URL と担当別トークンを入力し、手動再取得する。
8. 初期マスタが未登録の場合は責任者がマスタを確認して同期更新する。
9. テスト用の山を作り、下見→落札→原価→完了→差戻しを試してから切り替える。

## 注意
- 旧GAS/シートの登録内容は自動移行しない。旧シートの構造が未確認のため、移行前にデータ形式を確認する。
- 台帳は追記型の正本。並べ替え、手入力修正、行削除はしない。確認時はフィルタビューを使う。
- 操作履歴を残し、取消は論理削除。責任者のみマスタ更新・落札状態管理・取消が可能。スタッフは見積・原価登録・完了が可能。
- 残額がある完了は確認後に許容し、残額を保存する。複数端末で原価が変更されたときは完了操作を拒否する。
- 旧HTMLとの互換性は保証しない。r3のトークン付き接続を使用。
- GASのJSONP互換のため読み取り時にトークンがURLに含まれる。端末内のlocalStorageにも保存する。PINは端末画面ロックであり、強い認証ではない。第三者への公開や端末共有に注意し、漏えい時はスクリプトプロパティのトークンを変更する。強い認証が必要なら同一オリジンの認証付きAPIに移行する。
- 台帳全行を読み込むため、大量データでの性能は未検証。
- Google実環境のデプロイ、権限、通信、実機は未検証。GitHubの本番ブランチは未変更。
